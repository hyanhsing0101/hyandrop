# HyanDrop 功能设计文档

- **状态：** 已确认的首版方案
- **版本：** 0.1
- **更新时间：** 2026-09-07

## 1. 产品定义

HyanDrop 是一个响应式 Web 临时交换空间。用户无需注册、密码或账户，即可创建一个私密房间，通过分享链接或二维码在不同设备间传递文字与文件；房间中的内容在最后一次成功传输 24 小时后自动销毁。

首版服务于创建者本人，同时允许被邀请的人使用。它应是一个可公开上线并展示在简历中的完整产品，而不是仅限本地设备的演示页面。

### 1.1 产品原则

- **无账户：** 不收集邮箱、手机号和密码，不设置登录流程。
- **隐私优先：** 内容在浏览器加密，服务端只保存密文与必要的运行元数据。
- **链接即钥匙：** 加入房间只使用分享链接或二维码；不做手输房间码。
- **临时且明确：** 默认 24 小时过期，创建者可一键且不可撤销地销毁房间。
- **简单可靠：** 先完整实现文本、文件、图片预览及错误恢复，再扩展大文件、文件夹和实时协作。

## 2. 首版范围

| 能力 | 首版行为 |
| --- | --- |
| 使用身份 | 浏览器生成匿名设备身份和昵称，不注册、不登录 |
| 创建与加入 | 创建房间；复制分享链接、展示二维码；打开链接即加入 |
| 内容 | 加密文本、链接（作为文本）、文件；图片在浏览器内预览 |
| 容量 | 单文件最大 100 MB；房间已完成内容总量最大 200 MB |
| 有效期 | 最后一次成功发送文字或完成文件上传后起算 24 小时；只浏览、加入或下载不续期 |
| 房间记录 | 当前浏览器的“我的房间”列表；链接再次打开也能重新进入 |
| 状态 | 成员最近活跃、上传进度、发送/失败/完成状态和新内容提示 |
| 删除 | 创建者在本设备上一键销毁整个房间及全部文件；内容发送者可删除自己尚未过期的内容 |
| 传输可靠性 | 完整性校验、上传状态、失败提示和重新上传；完成后的内容才会在房间中可见 |

### 2.1 明确不在首版内

- 账户、密码、邮箱/手机验证、跨浏览器身份恢复
- 手输房间码、PIN、文件夹上传、超过 100 MB 的文件
- 文件中断后的分块断点续传、跨设备继续未完成上传
- 视频、音频、Office/PDF 等非图片文件的在线预览
- 公共房间搜索、联系人、长期存储、分享外链下载
- 验证码、举报、后台审核、IP 设备限速等反滥用功能
- 多实例 WebSocket 广播和复杂的即时协作

## 3. 匿名身份与访问模型

### 3.1 设备身份

第一次访问时，浏览器生成一个高随机度的 `device_id`，并保存到 IndexedDB；用户可修改本机昵称。服务端为该 ID 记录房间内的首次加入和最近活跃时间，用于展示匿名成员状态、标记内容发送者及审计运行事件。

这不是硬件指纹：不采集硬件序列号，不依赖浏览器指纹来跨设备追踪。清除站点数据、换浏览器或换设备都会得到新身份；这是无账户方案的预期边界。

### 3.2 分享链接

标准链接形式为：

```text
https://drop.example.com/r/<高随机度房间 ID>#<房间密钥>
```

- 路径中的房间 ID 用于定位房间，必须不可枚举。
- `#` 后的房间密钥只由浏览器读取，HTTP 请求不会携带它，因此服务端不会存储或记录该密钥。
- 二维码只编码同一条链接。二维码不是另一种鉴权方式。
- 收到链接的人即可看到并发送房间内容；链接转发等同于授权。首版不支持撤销某个接收者的访问权。
- 打开链接后，该房间会保存到该浏览器的“我的房间”。清除浏览器数据后，仍可凭原分享链接重新进入；同时丢失链接则无法找回。

### 3.3 创建者的唯一额外能力

创建者不拥有踢人、审核或删除他人内容的常规管理权。唯一额外能力是“销毁房间”。创建时服务端签发一个仅用于销毁的随机令牌；服务端只保存令牌哈希，令牌本身保存在创建者的 IndexedDB，且绝不出现在分享链接中。

点击“销毁房间”须二次确认。成功后立即阻断访问、删除数据库记录并异步删除所有对象；操作不可恢复。创建者清除浏览器数据后会失去此能力，房间仍会按期限自动过期。

## 4. 端到端加密设计

### 4.1 目标与边界

浏览器使用 Web Crypto API 生成高随机度房间密钥。文本和文件在离开浏览器前使用 AES-GCM 加密，每项内容使用独立随机 nonce；服务端、数据库和对象存储只接收密文、nonce、密文校验值以及最小化的运行元数据。

文件名、原始 MIME 类型、文本内容和图片像素都属于加密内容。图片预览由接收方浏览器下载并解密后生成，不创建服务端缩略图。

这不意味着服务端完全看不到使用痕迹。服务端仍会看到 IP、时间、匿名设备 ID、房间 ID、密文大小、上传状态和对象生命周期；拥有分享链接的人也可读取内容。终端被攻破、链接外泄或接收者再次转发，均不在加密保护范围内。

### 4.2 密钥恢复限制

服务端没有房间密钥，也不提供找回通道。这是无账户端到端加密的必要代价：遗失链接/密钥，或清除本地保存的链接后，内容无法恢复。界面必须在创建和分享时提示用户妥善保存链接。

## 5. 核心用户流程

### 5.1 创建房间

1. 用户打开首页，浏览器确保已存在匿名设备身份。
2. 用户点击“创建临时房间”。
3. 浏览器生成房间密钥；服务端创建空房间并返回房间 ID 与仅创建者持有的销毁令牌。
4. 页面进入房间，显示复制链接、二维码、24 小时规则和 200 MB 容量计数。
5. 房间保存到“我的房间”。

### 5.2 加入与再次进入

1. 用户打开分享链接或扫描二维码。
2. 浏览器从 URL fragment 读取密钥，并请求加密的房间记录。
3. 成功解密后显示内容；浏览器把房间保存到“我的房间”。
4. 同一设备以后可从首页“我的房间”直接进入；其他设备须再次拥有分享链接。

### 5.3 发送文本

1. 用户输入文字或链接并发送。
2. 浏览器加密内容和显示所需元数据，提交密文。
3. 服务端持久化成功后才返回“已发送”，并将房间有效期重置为 24 小时。
4. 在线客户端通过轻量实时通知刷新内容；通知失败时轮询兜底。

### 5.4 上传文件

1. 客户端在选择文件后、开始传输前请求当前容量限制。
2. 客户端以文件大小预检查单文件 100 MB 和房间剩余容量；服务端在创建上传会话时再次原子校验，防止多个客户端并发超额。
3. 文件在浏览器加密后上传到临时对象；生产环境优先使用私有 OSS 的短时签名上传，开发环境可使用本地存储适配器。
4. 客户端报告完成，服务端验证密文大小和摘要，原子地将文件从“上传中”转为“可见”，并重置房间有效期。
5. 未完成、超时或校验失败的临时对象不会出现在房间记录中，并由清理任务删除。

达到 200 MB 时显示已满并拒绝新的文件上传；不自动删除旧内容。文字消息不计入此文件容量配额，但应有独立的合理长度限制。

### 5.5 查看与删除

- 文本显示解密后的内容；链接可点击打开。
- 图片在本地解密后显示缩略图和全图预览。
- 其他文件显示加密前的文件名、大小和下载操作；用户下载后由浏览器解密并保存。
- 发送者可删除自己的内容。创建者可点击“销毁此房间”删除全部内容；普通成员不可清空整个房间。

## 6. 可靠性、容量与过期

### 6.1 首版的“不中途丢失”定义

首版保障已经标记为完成的文字和文件不会因刷新页面而丢失，并且文件只有经摘要校验后才对房间成员可见。上传失败时界面保留明确的失败原因和“重新选择并上传”操作。

首版不承诺网络中断后从字节位置继续。因为尚未实施分块上传，刷新页面或中断后需重新选择文件并从头上传；浏览器也通常不能在刷新后安全地重新取得原文件句柄。这是将复杂度控制在首版范围内的有意取舍。

### 6.2 配额防并发超额

服务端维护 `used_bytes + reserved_bytes`。开始上传时预留文件大小，完成时把预留转为已用空间，失败或超时后释放预留。所有预留和完成操作必须在数据库事务中完成，因此多个成员同时上传也不会突破 200 MB。

### 6.3 到期与清理

- 每次成功发送文本或完成文件上传，将 `expires_at` 更新为当前时间加 24 小时。
- 定时任务删除过期房间、数据库项、临时上传会话及对应对象；对象存储生命周期规则作为兜底。
- 手动销毁先让房间立即不可访问，再执行对象删除；清理失败应有可重试任务和告警。
- 下载、查看、加入均不续期，避免被动访问让数据无限留存。

## 7. 主要数据模型

| 实体 | 最小字段与用途 |
| --- | --- |
| `rooms` | 不可枚举 ID、到期时间、已用/预留字节、创建时间、销毁令牌哈希 |
| `room_devices` | 房间 ID、匿名设备 ID、加密昵称、首次加入/最近活跃时间 |
| `items` | 房间 ID、发送者匿名 ID、类型（文本或文件）、密文、nonce、密文摘要、创建/到期时间 |
| `files` | item ID、密文对象键、密文大小、上传状态、摘要、创建/到期时间 |
| `upload_sessions` | 文件 ID、预留大小、状态、超时与幂等键，用于保证上传完成的原子性 |
| `cleanup_jobs` | 删除目标、重试次数和结果，用于确保过期及手动销毁最终清理对象 |

数据库中不保存明文消息、明文文件名、房间密钥或销毁令牌本身。

## 8. 页面与交互

### 首页

- 产品说明与“创建临时房间”主操作。
- “我的房间”：按最近活动排序，显示本地保存的房间、剩余有效时间和进入操作。
- 解释无账户、24 小时销毁和链接遗失无法找回三个关键规则。

### 房间页

- 顶部：容量、剩余时间、复制链接、二维码、退出与创建者可见的销毁操作。
- 主区域：按时间排序的内容流；图片预览；文件下载；匿名昵称与发送时间。
- 底部：文字输入、文件选择/拖放、上传进度和错误重试。
- 窄屏优先：所有操作能在手机浏览器单手完成，上传和分享按钮保持显著。

## 9. 安全与运维底线

- 仅通过 HTTPS 提供服务；禁止 HTTP 链接。
- PostgreSQL、Redis 和对象存储桶保持私有，不映射到公网；应用密钥只存在未提交的生产环境配置中。
- OSS 使用最小权限、短时签名上传/下载、限制 CORS 来源，并设置对象生命周期。
- API 实施请求体、文件大小、内容长度和频率限制；首版没有完整反滥用系统，但接口需保留限流中间件位置。
- 记录结构化的运行日志和错误指标，但绝不记录 URL fragment、房间密钥、明文内容、销毁令牌或带完整查询参数的分享链接。
- 正式面向公网前，完成域名、TLS、备份与恢复演练，并按服务所在地的适用要求完成合规事项。

## 10. 版本路线图

| 阶段 | 目标 |
| --- | --- |
| 0.1 首版 | 本文定义的匿名链接房间、端到端加密文本/文件、图片预览、100 MB/200 MB 配额、可靠清理和响应式 Web |
| 0.2 可靠性 | 加密分块上传、断点续传、上传队列恢复、对象存储直传完善、速率限制 |
| 0.3 协作与安全 | WebSocket 多实例广播、扫码优化、可选房间 PIN、举报与滥用防护、管理处置流程 |
| 后续 | 文件夹、更多预览类型、可选跨设备恢复机制；任何恢复机制都必须重新评估端到端加密边界 |

## 11. 首版验收标准

1. 新用户无需输入任何个人信息，能创建房间并生成可用链接和二维码。
2. 两台设备凭同一分享链接可在 24 小时内看到彼此发送的文字、文件与图片预览。
3. 服务器、数据库和对象存储中无法直接读取消息内容、文件名或图片内容。
4. 单文件超过 100 MB 或房间累计文件超过 200 MB 时，上传在开始前被拒绝；并发上传也不能绕过限制。
5. 文件校验失败或上传中断时，房间不显示残缺文件；用户能重新上传。
6. 成功发送内容后有效期重置；仅浏览或下载不重置；到期后的房间和对象最终被清理。
7. 创建者的一键销毁可让房间立即不可访问，并最终删除其所有对象。
8. 手机与桌面浏览器均能完成创建、分享、发送、预览、下载和销毁流程。
